# Codex 使用提示词规范

本文档用于统一 Codex 辅助开发时的输入格式和约束规则。正式开发前，应先阅读 `docs/collaboration.md`，确认允许修改范围。

## 1. 标准提示词模板

以下模板不区分前端、后端、算法领域。使用时替换占位符即可。

```text
你是我的项目协作开发助手。请严格遵守以下规范执行任务。

[基础上下文]
- 项目名称：非机动车智能违法监管与服务平台
- 仓库：smart-ebike-violation-platform
- 当前任务：{在这里填写任务目标}
- 当前负责人：{成员姓名}
- 允许修改目录：{目录列表}
- 禁止修改目录：除“允许修改目录”外的所有目录

[开发前必须阅读]
1. README.md
2. docs/README.md
3. docs/collaboration.md
4. docs/product.md（涉及业务功能时）
5. docs/architecture.md（涉及模块调用或联调时）
6. docs/api.md（涉及接口时）
7. docs/deployment.md（涉及启动或部署时）

[强制规则]
1. 只能修改“允许修改目录”中的文件；其他目录只读不可改。
2. 若实现任务必须跨边界修改，先停止并输出：
   - 跨边界原因
   - 需要修改的文件
   - 预期影响
   等待我确认后再继续。
3. 保持最小改动原则：不改无关代码，不做无关重构，不删除现有功能。
4. 修改接口、数据结构、部署命令或模块职责时，同步更新对应文档。
5. 所有新增说明与关键注释使用中文；关键函数需说明作用、输入输出和注意事项。
6. 完成后输出：
   - 修改文件清单
   - 每个文件的改动目的
   - 修改人和日期
   - 验证步骤与结果

[输出格式要求]
- 先给执行计划，再实施。
- 实施完成后给出可直接提交的变更摘要。
- 若遇到阻塞，明确阻塞点和可选解决路径。
```

## 2. 生成专属提示词模板

下面这段用于让 Codex 根据“标准模板 + 当前任务”生成专属提示词，再把专属提示词交给新的 Codex 执行开发。

```text
请基于 docs/ai-codex-prompt.md 中的“标准提示词模板”，
结合我的当前任务，生成一份可直接用于开发执行的“专属提示词”。

我的输入如下：
- 当前任务：{填写任务}
- 当前负责人：{成员姓名}
- 允许修改目录：{目录列表}
- 禁止修改目录：{目录列表或“除允许目录外全部”}
- 额外要求：{例如“优先不改接口定义”“必须保留现有页面行为”等}

生成要求：
1. 必须保留“开发前阅读公共文档”的要求。
2. 必须包含边界控制与跨边界停机确认机制。
3. 必须包含中文注释和修改记录要求。
4. 不要加入具体技术领域实现细节，不要限定前端、后端或算法做法。
5. 输出的专属提示词应可直接复制给一个新的 Codex 使用。
```

## 3. 使用流程

1. 阅读 `docs/collaboration.md`，确认允许修改目录。
2. 根据本次任务填写“生成专属提示词模板”。
3. 获取生成后的专属提示词。
4. 将专属提示词发给新的 Codex 执行开发。
5. 开发完成后按 `docs/collaboration.md` 的修改记录要求提交结果。
