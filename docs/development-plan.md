# 两周开发计划

本文档用于拆分阶段任务、明确交付物和验收标准。具体接口以 `docs/api.md` 为准，模块职责以 `docs/architecture.md` 为准。

## 1. 角色分工

实际开发前请填写负责人：

```text
前端负责人：YuzhSong
后端负责人：7nfc
模型服务负责人：YuzhSong
数据库负责人：7nfc
文档负责人：YuzhSong
```

如一人负责多个模块，应在任务说明中明确允许修改目录。

## 2. 第 1 周：前后端与数据库联通

目标：完成基础工程闭环，打通前端、后端、数据库。

| 任务 | 交付物 | 验收标准 |
| --- | --- | --- |
| 前端接口层与基础页面联调 | 用户违法列表、详情页面或管理员基础页面 | 页面能调用接口并展示演示数据 |
| 后端工程初始化 | Spring Boot 工程、基础配置、启动入口 | `mvn spring-boot:run` 可启动 |
| 核心实体与基础 CRUD | 用户、管理员、设备、违法事件相关接口 | 接口返回结构符合 `docs/api.md` |
| 数据库建表与初始化数据 | `schema.sql`、`init_data.sql` | MySQL 可执行脚本并生成演示数据 |
| 全链路联调 | 前端 -> 后端 -> 数据库 | 至少完成列表和详情查询闭环 |

第 1 周结束时，必须明确记录：

- 已完成接口。
- 未完成接口。
- 前后端字段不一致问题。
- 数据库脚本执行结果。
- 下一周阻塞点。

## 3. 第 2 周：模型接入与演示能力完善

目标：完成设备上报、模型识别、管理员审核和统计分析闭环。

| 任务 | 交付物 | 验收标准 |
| --- | --- | --- |
| 模型服务接入 | `/detect` 接口可用，后端可调用 | 上传图片后能返回识别结果 |
| 设备上报流程 | `/api/device/report` | 能生成违法事件记录 |
| 审核状态更新 | 管理员审核接口和页面 | 能把事件状态更新为确认或驳回 |
| 统计分析接口 | `/api/admin/statistics` | 能返回总量、今日数量、类型分布 |
| 演示数据整理 | 可复现的初始化数据和演示步骤 | 答辩演示前可稳定跑通 |

第 2 周结束时，必须完成：

- 一条完整演示链路：设备上报 -> 模型识别 -> 事件入库 -> 管理员审核 -> 用户查询。
- 一份演示步骤说明。
- 一份已知问题清单。

## 4. 风险与处理

| 风险 | 影响 | 处理方式 |
| --- | --- | --- |
| 后端工程未初始化 | 前后端无法联调 | 优先完成 Spring Boot 工程骨架 |
| 接口字段反复变化 | 前端联调成本升高 | 以 `docs/api.md` 为唯一契约 |
| 模型服务耗时或依赖异常 | 设备上报流程不稳定 | 保留 mock 识别返回，保证演示闭环 |
| 数据库脚本与实体不一致 | 接口查询失败 | 修改表结构时同步更新脚本和文档 |
| 分工边界不清 | 容易互相覆盖修改 | 按 `docs/collaboration.md` 维护责任目录 |
